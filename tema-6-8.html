Qué tiene un simulador

Un simulador es un bucle en el tiempo que, en cada paso \(h\), calcula las derivadas del modelo con el estado actual y avanza el estado con un método numérico.

Hacen falta cinco cosas: parámetros del modelo, variables de estado con su condición inicial (una por cada una), entradas en función del tiempo, el método de integración con su paso \(h\), y qué salidas guardar para dibujarlas.

El orden de cada paso es siempre el mismo: leer la entrada en \(t_k\), calcular el control si toca, evaluar las derivadas, avanzar el estado, guardar y avanzar el tiempo. La plantilla en pseudocódigo para el examen está en Métodos numéricos.

Del pseudocódigo a Matlab

Ejemplo mínimo: un sistema de primer orden \(\tau\dot y+y=Ku\) con \(K=2\), \(\tau=0{,}5\) s y escalón \(u=1\), simulado con Euler.

K = 2; tau = 0.5; h = 0.01; N = 200;   % 2 s de simulación
u = 1;
y = zeros(1, N+1);                      % y(1) es y(0)
for k = 1:N
    dy     = (-y(k) + K*u) / tau;       % derivada con el estado actual
    y(k+1) = y(k) + h*dy;               % paso de Euler
end
t = (0:N)*h;  plot(t, y)

Con estos datos Euler da \(y(2)=1{,}9648\) y la solución exacta \(K(1-e^{-t/\tau})\) vale \(1{,}9634\). Con \(h=0{,}1\) Euler da \(1{,}9769\): el error crece con el paso. La misma ecuación con ode45 se escribe con una función anónima:

f = @(t, y) (-y + K*u) / tau;
[t, y] = ode45(f, [0 2], 0);

Trampa de índices

En Matlab los vectores empiezan en 1: no existe y(0). El \(y(0)\) de la teoría es y(1), y por eso y tiene N+1 posiciones.

Los números de este ejemplo se han comprobado con Python; el código Matlab no se ha podido ejecutar aquí (no hay Matlab ni Octave en el entorno de trabajo).

Elegir el solver en Simulink

El solver es el método numérico que decide el siguiente instante de la simulación y avanza el estado. Se elige en Configuración del modelo → Solver. Hay tres decisiones, en este orden:

  1. Paso fijo o variable. Con paso fijo el \(h\) no cambia; con paso variable el solver lo ajusta para cumplir las tolerancias de error. Si el modelo va a generar código para tiempo real hay que usar paso fijo; si no, el paso variable suele ahorrar muchos pasos.
  2. Explícito o implícito. Los explícitos sirven para sistemas no rígidos; los implícitos están pensados para ecuaciones rígidas (ver rigidez).
  3. Un paso o multipaso. Un paso usa solo el valor anterior; multipaso usa varios (necesita arrancar con un método de un paso).
SolverTipoCuándo usarlo
ode45variable, explícito, un paso (Runge-Kutta)Primera opción para casi todo; es el que Simulink usa por defecto en paso variable

Receta de la propia documentación de Simulink. Empieza con ode45. Si la simulación va lenta, el problema puede ser rígido: prueba un solver implícito. Para paso fijo, compara con el resultado del paso variable y prueba ode1; si no basta, sube a ode3 y después a ode5, y si aun así no es exacto reduce el paso.

Ejemplo del material: el péndulo en Matlab y Simulink

El material incluye un script de Matlab y un modelo de Simulink del mismo péndulo con fricción, \(\ddot\theta=-9{,}8\sin\theta-\dot\theta\), con \(\theta(0)=\pi/2\) y 10 s de simulación. El script simula tres versiones a la vez, cada una con su método:

  • Euler no lineal, con \(\sin\theta\).
  • Euler linealizado, sustituyendo \(\sin\theta\) por \(\theta\).
  • Runge-Kutta de orden 2 (punto medio), con \(\sin\theta\).
x1(1) = pi/2 ; x2(1) = 0                    % estado inicial (theta, velocidad)
for i = 1:N
    x1(i+1) = x1(i) + h*x2(i);
    x2(i+1) = x2(i) + h*(-9.8*sin(x1(i)) - x2(i));       % Euler no lineal
    K1 = xe1(i) + (h/2)*xe2(i);                          % RK2: estado en el punto medio
    K2 = xe2(i) + (h/2)*(-9.8*sin(xe1(i)) - xe2(i));
    xe1(i+1) = xe1(i) + h*K2;
    xe2(i+1) = xe2(i) + h*(-9.8*sin(K1) - K2);
end

El modelo de Simulink equivalente tiene cuatro integradores, dos ganancias de valor 10, una función seno, una constante \(\pi/2\) para la condición inicial, y está configurado con ode45 y 10 s.

Con \(\theta(0)=90^\circ\) el ángulo está lejos de donde \(\sin\theta\approx\theta\), así que la versión linealizada se separa de la real, y el RK2 coincide con la referencia (Euler solo se le acerca con pasos muy pequeños): tienes las cifras en la cuestión 3 de junio de 2026.

Un paso de \(10^{-5}\) s

El script usa un millón de pasos para que Euler no se desvíe. Eso funciona, pero es una forma cara de compensar un método de orden 1: RK2 con un paso cien veces mayor (\(10^{-3}\) s) comete menos error: unos \(10^{-6}\) rad frente a unos \(3\cdot10^{-5}\) rad de Euler con \(10^{-5}\) s (comprobado con código frente a una integración de referencia).
